# 駕駛提醒：起步提醒與車道偏離警示

兩個都是「看一眼就要能懂、而且不能亂叫」的功能，所以門檻與遲滯寫得比偵測本身還囉嗦。
兩個都會響一聲短提示音（`ToneGenerator`，2 秒內只響一次）—— 畫面在右半邊，
駕駛未必在看，沒有聲音等於沒有提醒。

## 起步提醒（`StartAssist.kt`）

停著的時候，**前車開走了**或**紅燈轉綠了**就提醒。兩種分開判斷、分開回報，
因為實際上常常只有一種看得到：路口排第二台以後紅綠燈被前車擋住，排第一台則看不到前車。

### 前車啟動

| 條件 | 值 |
|---|---|
| 自車停住 | < 2 km/h |
| 停多久才開始盯 | 1.5 s |
| 前車範圍 | 正前方 \|x\| ≤ 1.4 m、z ≤ 14 m，先要出現在 9 m 內 |
| 觸發 | 比「停著這段期間的最近距離」再拉開 1.5 m |

用**最近距離**當基準而不是第一次看到的距離 —— 前車常常會再往前蹭個半公尺，
用第一次的距離會太早叫。

**刻意不做「前車消失就提醒」**：四顆鏡頭輪流偵測，同一台車本來就會斷斷續續。
前車真的開走時距離會先一路拉開再離開偵測範圍，用距離判斷就夠，而且不會亂叫。

### 紅燈轉綠

要先在停住狀態下看到**夠有把握的紅燈（或黃燈）撐過 1.5 s**，之後綠燈撐過 0.4 s 才提醒。
只看到綠燈不算 —— 一停下來就看到綠燈，代表不是為了它停的。
號誌信心 < 0.5 不算數。號誌被前車擋住時**紅燈記憶會留著**（不然永遠等不到提醒），
只有綠燈的計時會歸零。

### 共通

- **一次性**：叫過就不再重複，直到自車真的動了（≥ 3 km/h）才重新武裝。
- 2～3 km/h 之間（龜速前進）維持現狀，不武裝也不解除。
- **顯示 5 秒就自己收掉**（`ALERT_MS`）。

### 為什麼要自己收掉

本來這是個「狀態」：叫了之後一直為真，等自車動起來才清掉。
但車速訊號多半有變化才廣播、停著時會過期，為了讓停著時還判得出來，
斷訊時會沿用最後那個「停著」的讀數（見下一節）——
於是**跟著前車開走之後，如果一直沒有新的車速送來，就以為還停著，提示永遠不會消失**。
使用者回報的就是這個。

這本來就該是**通知**而不是狀態：響一聲、顯示幾秒、自己消失。
這樣不管判不判得出來「已經開走了」，都不會卡住。
`index.html` 那邊的 `GO_TTL` 只是串流斷掉的保險（1.2 s），顯示多久由 `ALERT_MS` 決定。

### 車速訊號過期的處理（很重要）

車速訊號多半是**有變化才廣播**，而 `VehicleSignals` 2 秒就讓它過期 ——
停在紅燈前不動，第 3 秒起 `speedKmh` 就是 `null` 了，**正好是這個功能要用的時候**。

所以 `StartAssist` 自己記住最後一次有效車速：最後一次讀到的是「幾乎沒在動」（< 2 km/h）、
之後一直沒有新值，就當作它還是沒動（真的動起來，會變才廣播的訊號就會送新值過來）。
最多沿用 3 分鐘（`STALE_STOP_MS`），再久就不猜了。
最後一次讀到的是「在動」然後訊號斷掉 → 狀況不明，**不**當成停著。

一開始就完全沒有過車速訊號才是真的不作用 —— 那分不出「前車開走」和「自己在走」。

### 車速訊號從哪來

| 來源 | 需要什麼 | 備註 |
|---|---|---|
| GPS（`MapSource`） | 定位權限 + 收得到訊號 | 地下停車場沒有 |
| 車機廣播 `Voice_Speed_State` | 無（被動接收，一律開著） | **這台車機掃不到這個 action** |
| 車機廣播 `com.ts.main.auto_avm_speed_change` | 同上 | 掃描 52 個 App 的 170 個候選廣播，這台是這個 |
| AIDL `GetSpeed()` | `headUnitBind` 打開 | v0.4.8 起**預設開啟**（重啟其實是「監聽廣播」造成的，不是綁定） |

掃描使用者車機的結果裡**沒有** `Voice_Speed_State`，只有 `com.ts.main.auto_avm_speed_change`
和 `com.ts.main.mcustate`（都來自 `com.ts.MainUI`）—— 所以 `Voice_*` 那組很可能是別款車機的。
兩組現在都掛著收（廣播是被動接收，多掛幾個沒有風險）。
`com.ts.*` 這兩個的 extra 鍵名不明，所以先認 `Signal_State`，認不到就掃所有 extra、
取第一個落在 0–320 的數值（鍵名排序後再掃，結果才不會隨 Bundle 順序跳動）。

**還沒確認**：那份掃描記錄停在「掃描完成，可以按『開始監聽 60 秒』」—— 監聽沒有跑，
所以目前沒有任何一筆「實際收到車身廣播」的證據。按下去跑完把檔案給我，就能確定是哪一個 action、
鍵名是什麼、以及它是定期送還是有變化才送。

## 車道偏離警示（`LaneDepartureWarning.kt`）

吃 `RoadExtractor` 在俯視圖上找到的標線，算自車**車輪外緣**離左右那條線還有多遠。

| 條件 | 值 |
|---|---|
| 作用速度 | ≥ 55 km/h |
| 警示距離 | 車輪外緣離線 ≤ 0.15 m（實線 0.25 m） |
| 要在靠近 | 橫向速度 ≥ 0.12 m/s |
| 解除／重新武裝 | 離線 > 0.55 m |

### 幾個刻意的選擇

- **要「正在靠過去」才警示。** 只看距離的話，本來就貼著線開（窄路、路邊停車旁）會一直叫。
  橫向速度由線的位置跨幀差分、再做時間常數 0.4 s 的平滑。
- **打方向燈往同一邊偏不算。** 那是在變換車道 —— 方向燈方向與偏離方向一致就整個跳過，
  連距離都不判。燈熄掉後還寬限 1.2 s，因為變換車道的動作會跨過燈熄的那一刻。
  打**反方向**的燈卻往這邊偏，還是會叫（那不是在變換車道）。
- **低速不作用。** 巷弄、停車、塞車壓線是常態。沒有車速訊號一樣不作用。
- **只認縱向的線**（|dz| / 長度 > 0.62，約 ±52°）：橫過去的停止線、斑馬線不是車道邊界。
- **實線門檻放寬一點點**（0.25 m vs 0.15 m）：多半是路緣或禁止跨越，跨過去後果比較嚴重。

線段的 z 不跨過 0 時取最近的那一端 —— 只看得到前方一段線是常態（後方被車身蓋住），
不能因此就不判斷。

### 依賴

LDWS 吃的是 `road.lines`，而 `road` 只有在**地面模式 = 虛擬道路**時才會更新。
實景地面模式下 `RoadExtractor` 不跑，LDWS 就沒東西可吃。

## 顯示

| 提醒 | 畫面 |
|---|---|
| 起步 | 碰撞預警底下一條**綠色**膠囊：「▶ 前車已起步」／「▶ 綠燈了」／「▶ 綠燈了，前車也走了」，6 秒後收掉 |
| 車道偏離 | 畫面**左／右邊緣一條橘色光柱**在閃，餘光就看得到，不用把視線移過來；0.9 s TTL（偏離是連續狀態，停了就該馬上收） |

起步提醒刻意用綠色而不是紅／橘 —— 它是「可以走了」，不是「危險」。

## 測試

`StartAssistTest`（16 個）、`LaneDepartureWarningTest`（11 個）都是行為測試，
重點放在**不該叫的時候不要叫**：

- 自己在走的時候前車拉開 → 不叫
- 一開始就沒有車速訊號 → 兩個都不作用
- 停住後車速訊號過期 → 起步提醒仍要能叫（否則等於沒做）
- 最後讀到的是「在動」然後訊號斷掉 → 不當成停著
- 旁邊車道的車開走 → 不是前車
- 只看到綠燈（沒先看到紅燈）→ 不叫
- 號誌信心不足 → 不算數
- 打同方向燈偏離 → 不叫；打反方向燈 → 照叫
- 方向燈熄掉後的寬限期 → 不叫
- 一直貼著線穩穩開 → 不叫
- 橫過去的停止線 → 不是車道邊界
- 叫過之後回到車道中間 → 要能再叫（不是一輩子一次）

## 倒車入庫路徑（`ParkingPathPlanner`）

**v0.4.10 才接上畫面** —— 在那之前這個類別寫好了但沒有任何地方用到它。

挑**最近的空格**（垂直 `p` 或斜向 `a`；平行停車是另一種解法，planner 回 null）算一條路徑，
三段式：前進直線 → 倒車圓弧（半徑 = 1.1 × 最小迴轉半徑）→ 倒車直線。
格子多的時候只試最近 3 個。只在**車速 < 15 km/h 或車速不明**時給，
不然開在路上會一直閃。

畫面上：**青色 = 前進段、琥珀色 = 倒車段、綠色框 = 停好之後的車身位置**。

前提是**先要找得到空格**。停車格偵測本身的狀況見 [`parking-slots.md`](parking-slots.md) ——
目前驗證過的只有「自己停的那一格」，空格還沒有實車資料驗證過。

## 路口轉彎預判（`TurnPathPlanner`）

打了方向燈、方向盤也開始轉的時候，畫出接下來 16 m 會掃過哪裡。

跟另外兩條**不是同一個東西**：

| | 是什麼 | 長度 |
|---|---|---|
| `vehicle3d.js` 的方向盤軌跡 | 「**現在**輪子指向哪」，停車對位用 | 5 m |
| `LaneChangeAssist` 的 path | **變道**用；它偵測到在轉彎時會刻意不給路徑 | 到隔壁車道 |
| **`TurnPathPlanner`** | **路口轉彎**會掃過的走廊 | 16 m |

### 畫法：外側車頭角 + 內側後輪

兩條路徑分開畫，中間用橫向短線連成走廊。**兩條之間的差距就是內輪差** ——
台灣路口轉彎最常出事的就是這個：後輪比前輪走內側，捲進去的往往是旁邊的機車。

走廊裡有偵測到的物件（`conflicts()`）→ 整組從琥珀色轉**紅色**。

### 什麼時候才畫

方向燈和方向盤要**同時**成立：

- 方向燈打了，而且**方向盤轉的方向要跟方向燈一致**（反向代表在閃避或回正）
- 方向盤已經轉過 **30°**
- 車速 < **40 km/h**（高速打燈是變道，不是路口轉彎）

**打了燈但方向盤還沒轉就不畫。** 那時候「轉彎路徑」要畫在哪只能用猜的 ——
路口在幾公尺外、要用多大的半徑，都不知道。
猜一條畫得煞有其事比不畫更糟。方向盤一轉就會出現，那時候的弧線是從實際轉角算出來的。

**前提是拿得到方向盤角度**，而那只有車機 AIDL 有（「車身訊號」開關，v0.4.8 起預設開啟）。

## 另外兩種輔助線為什麼可能看不到

| 輔助線 | 在哪 | 需要什麼 |
|---|---|---|
| 轉彎（方向盤軌跡、內輪差） | `vehicle3d.js`，payload 的 `veh` | **方向盤角度**。只有車機 AIDL 拿得到（`headUnitBind`，v0.4.8 起預設開啟）。拿不到角度就只會畫直的 |
| 路口轉彎預判 | `index.html` 的 `drawTurn`，payload 的 `turn` | 方向燈 + 方向盤轉過 30° + 車速 < 40 km/h |
| 變道路徑 | `lca3d.js`，payload 的 `lca.path` | `LaneChangeAssist` 判定有**變道意圖**（打方向燈或已經在偏移）才會出現；平常直行時本來就不該畫 |
| 倒車入庫 | `index.html` 的 `drawPark` | 找得到空的垂直／斜向停車格 |
